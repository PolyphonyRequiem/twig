# Seeds and publication

A seed is an unpublished local Core draft with a durable UUID. A display alias
is not a provider identity, and a draft is not proof that remote creation
succeeded. Use `seed new/view/edit/validate` with the connected schema; structured
creation must choose an explicit parent or `--no-parent`.

Provider support is explicit. Qualified ADO parent/link/chain conveniences are
not a promise that GitHub accepts equivalent creation or relationships. Native
`Twig.Item` creation uses its separate durable user authority. Unsupported
fields, parents, relationship shapes and providers refuse.

Preview and publication use native Core proposal/digest/journal semantics.
Structured `seed publish` is refused because it depends on interactive context;
use the supported explicit machine change path and installed help. There is no
`proposal seed`, old PlanCommand seeder or automatic plan-to-ADO script.

After publication, verify the journal's exact published identity and refreshed
provider facts before reporting success. Preserve original draft/proposal/
digest/attempt evidence after an uncertain creation. Recovery observes original
authority/receipts and readback; it must not redispatch a possibly successful
creation or infer failure from a missing response.

See [seed commands](../commands/seeds/README.md) and
[current proposals](proposals.md).
