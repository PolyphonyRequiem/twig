# `twig plan validate`

```sh
twig plan validate --file change.json -o json
```

Run `twig plan validate --help` to get a complete seed creation example
generated by the canonical Plan writer. `twig pending -o json` lists the
UUIDs and typed values of staged seeds. The example's connection, schema,
policy and store values are illustrative; format validation does not establish
that they match a real target.

## Behavior

Requires an explicit current canonical Core plan file inside the admitted
workspace file boundary. Reports digest, format version and operation count.
`validationScope: "canonical-format"` and `applicationEvidenceChecked: false`
mean that process, policy and current execution evidence have **not** been checked.
Old plan v1/provider-plan v2 JSON is not translated.

## Effects

No provider request, journal import, draft change or publication.
Data-command workspace admission still applies.

## Failure modes

Missing file/invalid canonical input is an error. Syntax success does not imply
`canApply`; separately [preview](plan-preview.md) the exact file.
Human, JSON aliases and minimal inspection are supported, not `ids`.
